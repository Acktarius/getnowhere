Cap Holepunch NDJSON line size

TL;DR

A bad peer can today stream endless data without a newline and balloon Holepunch memory until the whole sidecar dies. After this change, lines over 256 KiB trip a hard stop: that peer connection is dropped; your other rooms keep running.

What you'll get

  • Pending reassembly capped at 256 KiB (configurable).
  • Overflow drops only the offending peer connection.
  • A second config knob reserved for future file/media size (not used yet).
  • Finding note updated with the fix.

How it works

Peer sends Hyperswarm data
        ↓
Reassemble NDJSON until newline
        ↓
If pending buffer > 256 KiB → clear + destroy that connection
        ↓
Normal chat lines (tiny) parse as today

What changes for you

  • No UI change for normal sealed chat frames.
  • Limits live in holepunch-sidecar/config.json if you need to retune later.

Risks and open questions

  • Anything that truly needs NDJSON lines larger than 256 KiB will need a config bump or a different framing path.
  • Pictures should not ride this text line path — use the reserved file limit when media lands.

Out of scope

  • Sending/receiving pictures or files.
  • WebSocket message-size limits on the local bridge.
