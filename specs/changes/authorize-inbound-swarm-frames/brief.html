Authorize inbound Holepunch frames by shared topic

TL;DR

Outbound chat frames already go only to peers Hyperswarm says share that room. Inbound frames still trusted a peer’s self-labeled room id as long as you had that room open. After this change, inbound frames get the same check — foreign-labeled frames are silently dropped.

What you'll get

  • A peer connected only on room A cannot push frames into room B on your sidecar.
  • Same allowlist for send and receive on the swarm wire.
  • Finding note updated to match the post-hello-fix threat and remediation.

How it works

Each Hyperswarm connection tracks which topics it actually shares. When a sealed frame arrives, the sidecar delivers it to your UI only if that connection is listed for that topic. Otherwise it ignores the line — no disconnect, no error noise. 

Peer on connection sharing only A
        ↓
Sends frame labeled as room B
        ↓
Sidecar: B not on this connection → drop
        ↓
UI for room B never sees it

What changes for you

  • No new UI or commands.
  • Normal Alice/Bob chat when both rooms are truly shared still works once Hyperswarm associates the second topic.

Risks and open questions

  • Very brief drop window if a second shared topic is reported slightly after the first frames — same as today’s outbound filter.
  • Someone who already knows room B’s secret can still join B via the DHT; this only stops mis-labeling frames on an A-only link.

Out of scope

  • Reintroducing app-level hello.
  • UI, encryption, or invite flows.
