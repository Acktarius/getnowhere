iOS wallet backup share

TL;DR

On iPhone, Settings → Backup → download wallet JSON currently crashes because the app uses an Android-only save API. After this change, iOS opens the normal share sheet so you can Save to Files (or AirDrop). Android keeps working as it does today.

What you'll get

  • iOS: tap Download → system share sheet → Save to Files / share elsewhere.
  • Android: same folder picker / Downloads write as now.
  • Cancel or failure still shows an error in Backup (no silent “success”).

How it works

The phone shell receives the encrypted wallet JSON from the in-app UI. On Android it asks which folder to write to. On iOS it writes a temporary file and opens the share sheet so you choose where it goes. 

flowchart TD
  A[Backup: Download wallet.json] --> B[Mobile shell gets file content]
  B --> C{Platform?}
  C -->|Android| D[Folder picker / SAF write]
  C -->|iOS| E[Temp file + share sheet]
  D --> F[Success or cancel error]
  E --> F

What changes for you

  • iOS Backup download will feel like sharing a file, not a direct Downloads write.
  • No new settings screens or passwords — same Backup flow.
  • Needs a new iOS build that includes this native-shell fix.

Risks and open questions

  • You must pick Save to Files (or another destination) in the share sheet; the app cannot force a folder.
  • A short-lived temp copy may sit in app cache if cleanup fails — still app-private.

Out of scope

  • Changing Android’s save UX.
  • Showing the app’s Documents folder in Files without sharing.
  • Changing seed reveal, export QR, or backup passwords.
