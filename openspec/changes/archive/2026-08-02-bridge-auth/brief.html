Harden sidecar bridge auth

TL;DR

Today Holepunch can listen on the LAN with no shared secret, and when a secret is set it is compared with a plain string check. After this change, binding off loopback without a token fails immediately at startup, and token checks use a timing-safe compare. Everyday local web-dev on 127.0.0.1 without a token stays allowed.

What you'll get

  • Sidecar refuses to start on non-loopback hosts unless GNH_SIDECAR_TOKEN is set.
  • Loopback (127.0.0.1, ::1, localhost) can still run without a token for web-dev.
  • When a token is set, wrong or missing ?token= still closes with 4001 — comparison is timing-safe.
  • Docs spell out the exception and the off-loopback rule.

How it works

flowchart TD
  A[Sidecar starts] --> B{Host loopback?}
  B -->|yes| D[Listen]
  B -->|no| C{Token set?}
  C -->|no| E[Exit before listen]
  C -->|yes| D
  D --> F[Client connects]
  F --> G{Token required?}
  G -->|no| H[Accept]
  G -->|yes| I{timingSafeEqual match?}
  I -->|no| J[Close 4001]
  I -->|yes| H

What changes for you

  • Normal npm run holepunch on localhost: unchanged.
  • If you bind Holepunch to 0.0.0.0 or a LAN IP, you must set GNH_SIDECAR_TOKEN or the process exits.
  • No Electron or UI workflow changes in this change.

Risks and open questions

  • Token still rides in the WebSocket URL query string (browser limitation) — not fixed here.
  • Desktop shared-mode default token string is unchanged — separate hardening.

Out of scope

  • Moving auth to a header / subprotocol / IPC-only channel.
  • Requiring a token on loopback.
  • Join/frame topic authorization (other findings).
