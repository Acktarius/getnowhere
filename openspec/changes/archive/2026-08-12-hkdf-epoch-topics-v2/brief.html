Stronger chat discovery topics (HKDF v2)

TL;DR

New chats will derive Hyperswarm discovery topics from relationship keys (HKDF + rotation epochs) instead of a plain hash of room ids. Existing chats keep working until recreated. Strategy docs land for layer separation and the local desktop bridge roadmap (ws → wss → IPC later).

What you'll get

  • Key-bound discovery topics — harder to grind from leaked id fragments.
  • Topic rotation on revoke or agreed bump (epoch), without widening invite message size.
  • Post-connect proof binds epoch so wrong-era peers fail closed.
  • Existing v1 rooms unchanged until destroyed or recreated.
  • Written security policy: Conceal distributes capabilities; Hyperswarm discovers; local bridge is control only.

How it works

Conceal Smart Messages still deliver the invite (4-byte room id unchanged). Both peers derive a relationship key from the existing handshake ECDH, then HKDF produces the swarm topic for the current epoch. Join + L1 proof as today.

  A->>D: Join topicRef
  B->>D: Join topicRef
  A->>B: Noise stream + L1 proof (epoch-bound)

What changes for you

  • New invites after upgrade use v2 topics automatically when both peers support it.
  • Old rooms reconnect with v1 topics until you leave and create fresh.
  • No UI change expected; Room diagnostics may show topic suite / epoch later.
  • Desktop still uses loopback WebSocket to the sidecar — wss and IPC are documented but not in this change.

Risks and open questions

  • Peer on old build + peer on new build need clear connect failure, not silent mismatch.
  • Epoch desync requires rare L1 sync message — watch diagnostics if connect fails after revoke.
  • Crypto/security independent review required before release.

Out of scope

  • Widening 4-byte room or invite ids (Conceal size budget).
  • wss:// sidecar, Unix socket / IPC migration, Ed25519 signed invites.
