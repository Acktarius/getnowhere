Wipe biometric on wallet delete

TL;DR. After you delete a wallet, biometric unlock will turn off (theme and other prefs stay). If an old install is already stuck on App Lock with no fingerprint enrollment, the app will clear that broken setting and let you in. You re-enable biometrics later in Security settings if you want them.

What you'll get

  • Delete wallet → no more App Lock demand until you opt in again.
  • Theme / network and other prefs still survive Delete wallet (Reset app data still wipes everything).
  • Devices already stuck after delete + re-import heal on next launch of the fixed build.

How it works

Delete already wiped the fingerprint credential but left the “biometrics on” switch true. This change flips those switches off when credentials are wiped, and adds a check at startup: switch on but no credential → turn switch off. 

flowchart LR
  A[Delete wallet] --> B[Clear native biometric]
  B --> C[Set biometric flags OFF]
  C --> D[Keep theme prefs]
  E[Cold start / import] --> F{Flag ON but no enrollment?}
  F -->|yes| G[Turn flag OFF — skip App Lock]
  F -->|no| H[Normal App Lock if needed]

What changes for you

  • After Delete wallet + import: open the app without a fingerprint gate.
  • To use biometrics again: Settings → Biometrics & auto-lock → turn on and enroll.
  • Until this build ships: Reset app data (or clear app storage) escapes the stuck lock screen.
Risks. Stuck phones need the updated APK for the auto-heal. Wrong enrollment probe could clear a valid flag — mitigated by using the same credential key the enroll path already uses, plus unit tests.

Out of scope

  • Changing how enroll / unlock looks.
  • Auto-turning biometrics back on after import.
  • Desktop / browser biometrics.
