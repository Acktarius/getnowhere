iOS Sync Checkpoint

TL;DR

When an iOS phone sleeps mid-sync, the wallet currently forgets all progress and rescans from scratch next time you open the app. This change makes the sync engine save its position every ~1000 blocks during a long catch-up, and also flushes the saved position the moment the app goes to background — so a restart after sleep picks up roughly where it left off instead of starting over.

What you'll get

  • After an interrupted deep sync on iOS, reopening the app resumes near the last saved block instead of restarting from the wallet's creation height.
  • Regular incremental syncs (already near the chain tip) are unchanged — no extra work happens on a phone that's up to date.
  • Android behaviour is identical to today — the same code runs; the extra saves are just additional idempotent writes during long catch-ups.
  • No new native iOS code, no native module changes, no App Store submission required for this fix.

How it works

The wallet sync runs inside a WebView on iOS. When iOS suspends the app, WebView JavaScript timers freeze immediately. Previously, the sync only saved progress once at the very end of each full scan pass — so a freeze between "started" and "finished" lost all progress.

Two complementary fixes are added:

  • Mid-sync checkpoint: During a long catch-up, the sync now saves progress to encrypted storage every ~1000 blocks. If iOS kills the WebView before the scan finishes, the next open resumes from the last checkpoint rather than from zero.
  • Background flush: When the app signals it is moving to background, a best-effort flush writes whatever progress has happened since the last save — protecting the most recent partial batch.

What changes for you

Nothing changes in the UI or any workflow. The wallet resumes faster after iOS interruptions — that's the only visible effect.

Risks and open questions

  • The background flush is best-effort: if iOS freezes the WebView before the flush JS executes, the last partial batch (up to ~1000 blocks) is still lost — but the checkpoint before that is safe. This is a best-effort improvement, not a guarantee.
  • Extra encrypt+write calls during deep catch-up add a small overhead (one save per ~1000 blocks). On a wallet that is 100 000 blocks behind, that's ~100 extra writes during catch-up — negligible compared to the hours of sync time.

Out of scope

  • iOS native beginBackgroundTask extension (would buy ~30s extra time; deferred as future hardening).
  • Any change to the Android WorkManager chain.
  • Changing how frequently progress is saved during normal (near-tip) sync.
