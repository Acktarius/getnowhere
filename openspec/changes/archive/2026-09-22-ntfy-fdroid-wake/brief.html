ntfy F-Droid wake

TL;DR. F-Droid and GrapheneOS users (no Google) will now receive instant peer-wake signals via our own self-hosted ntfy.getnowhere.im server — the same way that, today, iOS users get poked via Apple push. All Google / Firebase code is deleted. One unified pokeId mechanism works for both F-Droid (ntfy) and iOS (APNs) with no platform information exposed on the wire.

What you'll get

  • F-Droid users get woken within seconds when their contact sends a relay message (L1′), cutting the current ~30-second WorkManager poll gap.
  • iOS users continue to get woken via Apple push — no change to that path.
  • No Google Play Services, no Firebase, no FCM — anywhere in the codebase.
  • The Settings → Privacy "Wake contact on relay" toggle now controls ntfy subscription (F-Droid) or APNs registration (iOS). Toggle description updated to reflect this.
  • CI simplified: v*-f-droid tags build the F-Droid APK only; other v* tags build Electron desktop only. No GMS variant exists.
  • If a wake is missed (phone killed, Doze), the existing WorkManager and BGAppRefresh recovery paths remain unchanged — the chat message is never lost.

How it works

Each room generates a random 10-byte pokeId at invite time. Alice includes hers in chat.create; Bob includes his in chat.register. The pokeId becomes an ntfy topic capability (gnh-<pokeId>). Neither side learns the other's platform.

When Alice sends the first relay message after a live session drops, her app calls POST /poke { to: bobPokeId } on our gateway. The gateway checks its registry: if Bob registered an APNs token (iOS), it fires Apple push. If not (F-Droid), it POSTs wake to Bob's ntfy topic. Bob's F-Droid app subscribes to its own ntfy topic and calls the existing WorkManager sync worker on receipt. 

sequenceDiagram
    participant A as Alice (any platform)
    participant GW as poke-gateway
    participant APNS as Apple APNs
    participant NTFY as ntfy.getnowhere.im
    participant B_iOS as Bob (iOS)
    participant B_FD as Bob (F-Droid)

    A->>GW: POST /poke { to: bobPokeId }
    GW->>GW: DB lookup bobPokeId
    alt iOS registered
        GW->>APNS: push wake
        APNS->>B_iOS: wakes app → sync
    else F-Droid (not in DB)
        GW->>NTFY: POST gnh-bobPokeId "wake"
        NTFY->>B_FD: SSE message event → sync
    end
    GW-->>A: 202 Accepted (always)

One poke fires per L2-disconnect event (first L1′ after live drops), then a 5-minute cooldown. When the room ends (leave, expiry, invite timeout), both pokeIds are forgotten. No server-side revoke needed.

What changes for you

  • Settings toggle: "Wake contact on relay" description changes from "Uses Apple/Google push" to "Uses ntfy / APNs wake. No Google."
  • Environment: poke-gateway needs two new env vars — NTFY_BASE_URL and NTFY_PUBLISH_TOKEN (write-only ntfy credential).
  • ntfy server: must be configured with auth-default-access: deny-all; gateway gets a write-only credential for gnh-* topics.
  • CI: no more GMS APK matrix. v*-f-droid → F-Droid APK; other v* → Electron only (already reverted in commit d0c344e).
  • Secret removed: GOOGLE_SERVICES_JSON_BASE64 is no longer used or documented.

Risks and open questions

  • F-Droid process killed by Doze: wake is missed. Recovery via existing WorkManager (30s chain). Chat is always eventually consistent.
  • APNs silent push throttled by iOS: known and acknowledged. Poke is a hint, not the message.
  • ntfy server outage: F-Droid wakes stop. WorkManager recovers. Same failure mode as the gateway being down for iOS.
  • ntfy read credential management: per-topic read tokens for F-Droid devices are configured statically in this version. A per-device provisioning endpoint is deferred.

Out of scope

  • UnifiedPush distributor integration (user must install a separate app — not required here).
  • iOS ntfy subscribe path (iOS uses APNs; ntfy is Android-only in this change).
  • A per-device ntfy credential provisioning endpoint (static token in this version).
  • Wake for force-quit F-Droid processes (WorkManager is the recovery; this change does not add a foreground service).
  • Any Play Store / GMS APK build (deliberately removed).
