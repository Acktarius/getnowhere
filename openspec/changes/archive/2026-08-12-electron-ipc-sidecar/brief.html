Electron IPC sidecar

Operator brief — change electron-ipc-sidecar

TL;DR

The installed and dev desktop app talks to its networking helper over an ordinary local WebSocket today. That keeps a TCP port open on loopback. This change switches desktop to a private operating-system pipe or socket instead, while browser development keeps WebSocket for easy debugging.

What you'll get

  • Desktop Electron no longer opens a WebSocket from the UI to the sidecar.
  • The UI sends the same join / frame / ping commands through a typed bridge exposed by the desktop shell.
  • The sidecar still supports WebSocket when you run web-dev (npm run holepunch + npm run dev).
  • No bridge password on the IPC path — OS local access replaces loopback TCP guessing.
  • Alice/Bob dev testing continues to work with separate IPC paths in isolated mode.

How it works

sequenceDiagram
  participant UI as Desktop UI
  participant Shell as Electron shell
  participant Side as Sidecar

  UI->>Shell: typed command (join, frame, …)
  Shell->>Side: OS pipe / Unix socket
  Side-->>Shell: events (peers, frames, errors)
  Shell-->>UI: same events via preload bridge

Browser dev unchanged: UI connects with WebSocket to port 7901. Only the packaged and desktop:alice / desktop:bob paths use IPC by default.

What changes for you

  • No new commands for daily use — same app, stronger local transport on desktop.
  • Web-dev workflow unchanged.
  • Optional override GNH_HOLEPUNCH_WS_URL still forces WebSocket for debugging.

Risks and open questions

  • Stale socket files after a crash — startup cleanup handles this on Linux.
  • Windows named pipes need manual smoke on a real Windows build.
  • wss:// for future browser production is deferred.

Out of scope

  • Removing WebSocket from the sidecar
  • Mobile / Expo changes
  • Embedding the sidecar inside Electron main

Work overview

  • Sidecar IPC transport + shared message handler (~2 tasks)
  • Electron main IPC client + spawn wiring (~3 tasks)
  • Preload bridge + UI backend selection (~3 tasks)
  • Documentation (~2 tasks)
  • Verify unit + manual desktop smoke (~3 tasks)
