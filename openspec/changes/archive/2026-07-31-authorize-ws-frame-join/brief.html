Require join before sending Holepunch frames

TL;DR

Today any local app that opens the Holepunch WebSocket can push chat frames into a room someone else already joined. After this change, you must join that room on the bridge first — same rule the UI already follows.

What you'll get

  • A second local client cannot inject into a room it never joined.
  • Unauthorized frame attempts get a bridge error (not silent success).
  • Finding note updated with the fix.

How it works

Client must join(topic) first
        ↓
Only then frame(topic) fans out locally / to swarm
        ↓
Otherwise: error (WS) / no-op (mesh sendFrame)

What changes for you

  • No UI change if the app already joins before sending.
  • Misbehaving local scripts that skip join will stop working.

Risks and open questions

  • Alice and Bob sharing one sidecar can still both join any topic they know — product rule, not this fix.

Out of scope

  • Token / auth hardening beyond this membership check.
  • Hyperswarm inbound path (already fixed).

Work overview

  • WS joined check, docs, finding (1 task)
