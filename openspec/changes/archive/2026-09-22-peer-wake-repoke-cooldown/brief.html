Peer-wake re-poke cooldown

TL;DR

Today Bob’s first chain message after L2 drops can wake Alice once. If she ignores the banner and he sends again a few minutes later, nothing new is pushed. After this change, a poke can fire again once five minutes have passed since the last poke.

What you'll get

  • First L1′ after L2 drop still wakes Alice (unchanged).
  • Another L1′ within five minutes does not poke again (spam control).
  • Another L1′ after five minutes or more re-notifies Alice while still on relay.
  • Getting back on L2 still resets so the next drop can poke immediately.

How it works

Each room remembers when the last poke succeeded. On each chain (L1′) send we poke if wake is on, we know Alice’s handle, and either we never poked this stretch or at least 300 seconds have passed. The gateway’s own five-minute limit stays as a backstop.

What changes for you

  • No new Settings toggle — five minutes is fixed.
  • Testers: background Alice, have Bob send L1′, wait ≥5 minutes, send again — expect a second wake.

Risks and open questions

  • Does not fix missing APNs registration or empty gateway URL on builds — only re-poke timing.
  • If the gateway rejects a poke, the chain message still delivers; wake remains best-effort.

Out of scope

  • APNs register env field fix
  • Renaming helpers, Settings for the interval, gateway changes
