Multiple rooms with the same contact

TL;DR

You will be able to keep several chat rooms with the same person at once (different topics or expiries). Sending another invite will no longer silently kill the old room, and the misleading “this room was replaced” banner goes away. If you create another room with the same topic, the app asks you to confirm first.

What you'll get

  • Multiple live rooms per contact stay open side by side.
  • New invite = new room id; accept/decline still works as today for that invite.
  • Confirm dialog when creating a second room with the same topic.
  • No more “room superseded / open the new one” banner just because the contact’s latest room id changed.
  • Docs match: Leave/revoke ends a room; create does not auto-replace.

How it works

Contact detail still shows pending invites to accept or decline. Create always allocates a fresh room. The app only warns when you already have an open room on that topic. Older rooms remain in Chats until you leave them. 

Contact → Create invite (optional same-topic confirm)
        → New room appears in Chats
        → Peer Accept / Decline that invite
Existing rooms for that contact stay usable

What changes for you

Resend / create may ask “are you sure?” for the same topic. You will not see the old room branded as replaced when you open it. Explicit Leave still ends a room.

Risks and open questions

  • Chats list can grow if people create many parallel rooms.
  • Contact “open chat” shortcuts may still prefer the latest room id as a hint.

Out of scope

  • Peer count in room diagnostics.
  • Reworking contact storage to a full room-id list.
  • Crypto / topicRef formula changes.
