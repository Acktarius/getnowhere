Harden mobile P2P bridge

TL;DR

Android chat runs a WebView UI talking to a Bare Hyperswarm worklet through React Native. A security review found gaps: unbounded IPC buffering, weak bridge tokens, exposed secrets, permissive WebView settings, and missing rate limits. This change closes those holes to match desktop sidecar parity.

What you'll get

  • RN-side IPC line reassembly capped at 256 KiB; oversize kills the worklet.
  • Bridge tokens always from a CSPRNG; empty token refuses worklet start.
  • Bridge secret hidden from JavaScript on window.
  • WebView navigation locked to bundled asset URLs.
  • Rate limits on join/leave/frame with clear rate_limited errors.
  • Regression tests for auth and IPC caps.

How it works

WebView commands still use postMessage, but the native host holds the token in a closure. Bare worklet enforces auth and rate limits on every IPC line. RN caps incoming NDJSON the same way the sidecar caps Hyperswarm lines.

What changes for you

  • Normal chat behavior unchanged for valid frames under size limits.
  • Developers rebuild Android assets after bare bundle changes.
  • Tests run via npm run mobile:test-bare from repo root.

Risks and open questions

  • Tighter WebView flags may break asset loading — regression-test workers.
  • Hiding bridge token may require UI client updates if tests read window.gnhMobile.bridgeToken.
  • Rate limits must not block legitimate reconnect bursts during room open.

Out of scope

  • iOS Bare host (Android-only phase B today).
  • Replacing WebView with native RN UI.
  • Sidecar or Electron changes.
  • L1/L2 crypto or protocol payload changes.
