Fix QR wallet import

Awaiting your approval before any implementation.

TL;DR

Scanning a wallet backup QR currently fails because we treat it like an encrypted JSON file. We will decode the standard Conceal wallet QR format, ask for a new local wallet password (with confirmation), and never show or log the scanned secrets — only “Scan successful” after a good scan.

What you'll get

  • QR import works for spend keys, seed words, or view-only keys in the QR.
  • QR, seed, and keys: set a new wallet password (twice, with strength hints).
  • File import: unchanged — password that encrypted the backup file.
  • After a good QR scan: “Scan successful” — no address/key preview.
  • No logging of addresses, keys, mnemonics, or QR payloads during import.

How it works

Wallet QRs encode a text URI (conceal.ccx7…?spend_key=…), not JSON. We parse it silently, build the wallet, and encrypt locally with your chosen password.

flowchart LR
  scan[Scan QR] --> ok[Scan successful]
  ok --> pwd[Set new wallet password]
  pwd --> encrypt[Encrypt locally]
  file[JSON backup] --> decrypt[Backup password]
  decrypt --> encrypt

What changes for you

  • Import → QR: new wallet password flow; scan success message only.
  • Import → file: same backup password as today.
  • Keys “Preview address”: first 5 + last 5 chars only (e.g. ccx7a…xyz12).
    • Non-standard QRs that are encrypted JSON will still fail (matches conceal-next-wallet).

    Out of scope
