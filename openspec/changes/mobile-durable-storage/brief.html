Mobile durable storage

TL;DR

On some Android phones, leaving the app and coming back can wipe the wallet and settings because they live in the WebView’s short-lived storage. After this change, the phone keeps the wallet and preferences in native storage. The wallet file is encrypted. Web and desktop stay as they are.

What you'll get

  • Create or import a wallet on Android, kill the app, reopen — the wallet is still there.
  • Theme and settings survive the same restart.
  • If the wallet file is damaged, the app says it could not be opened and does not pretend you have no wallet.
  • Delete wallet / Reset app still wipe the durable copy on this device (logical delete, not forensic erase).
  • A missing native bridge shows a fatal screen instead of silently using WebView storage.

How it works

Before the UI starts, the phone app installs one storage adapter. Settings and contacts go into the existing native secure preferences. The wallet blob goes into a private encrypted file. Creating or deleting a wallet waits until that file write or delete finishes. Preferences may flush a moment later, but the wallet does not. 

flowchart TD
  Boot[Phone app starts] --> Install[Install native storage]
  Install --> Ready{Bridge ready?}
  Ready -->|no| Fatal[Fatal screen]
  Ready -->|yes| Read[Read prefs and wallet file]
  Read --> State{Wallet file}
  State -->|missing| Welcome[Normal Welcome]
  State -->|readable| App[Open existing wallet]
  State -->|unreadable| Error[Recovery screen — file kept]
  App --> Write[Wallet save waits for disk]
  Write --> File[Encrypted private file]

What changes for you

  • Existing test wallets stored only in the WebView will not come back. That is intended; there is no migration.
  • If you see “wallet data could not be opened,” do not create a second wallet over it.
  • Web and desktop behavior does not change.

Risks and open questions

  • Theme or other small prefs could still be lost if Android kills the app mid-flush. The wallet path waits for disk.
  • Full “kill the app on a real phone” proof is an operator smoke test. Automated tests cover the adapter, encryption envelope, wipe, and boot order.
  • iOS uses the same app contract. If the iOS file encryption grows too large, Android still ships encrypted; iOS may follow with a leftover TODO.
  • The wallet file and related secure prefs are kept out of Android Auto Backup / phone-to-phone transfer and iCloud backup. A restored copy without the original hardware key is treated as damaged, not as a new empty wallet.
  • Delete wallet removes the app’s current file and temp files. It does not promise to erase OS snapshots or backups that already left the device.

Out of scope

  • Copying old WebView data into native storage
  • Changing how the Conceal wallet blob itself is encrypted
  • Cloud backup or key recovery
  • Encrypting chat rooms or all preferences as files
  • Asking for biometrics every time the wallet file is read
