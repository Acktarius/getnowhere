iOS phone-only + TestFlight preview + APNs key

Operator brief for change mobile-ios-eas-apns-preview

TL;DR

After this change, the Expo wrapper is configured for iPhone-only builds, EAS can produce a TestFlight iOS preview from Linux, and docs tell you how to wire the Apple push AuthKey into poke-gateway. The key itself stays off git (already on the VPS).

What you'll get

  • Phone-only iOS app id settings (no tablet target)
  • An EAS preview-ios profile that builds iOS for TestFlight (Android preview stays internal APK)
  • A clear checklist: App ID → .p8 → VPS secrets → rebuild gateway

How it works

Product UI still ships inside the Expo wrapper. Linux cannot run Xcode, so EAS builds the IPA in the cloud. Peer wake on iOS uses Apple Push: poke-gateway signs requests with your AuthKey. F-Droid peers keep using ntfy when no APNs registration exists. 

flowchart LR
  Dev[Linux laptop] -->|eas build preview| EAS[EAS cloud]
  EAS -->|IPA| TF[TestFlight]
  TF --> Phone[iPhone]
  Phone -->|register token| GW[poke-gateway]
  GW -->|APNs .p8| Apple[Apple Push]

What changes for you

  • After merge: with root .env set, run npm run mobile:sync-ui, then eas build --platform ios --profile preview-ios, then submit to TestFlight
  • APNs AuthKey stays on the VPS only — not uploaded to EAS. Root VITE_* (poke URL + ntfy read token) bake into the app JS at sync time, same idea as the F-Droid APK

Risks and open questions

  • Production-only AuthKey will not wake sandbox/dev installs — TestFlight is the intended path
  • First EAS submit needs Apple/Expo login and an App Store Connect app for the bundle id

Out of scope

  • Agent-run cloud builds or committing the .p8
  • Dual sandbox + production keys in the gateway
  • App Store public release polish
