# Expo SDK 58 upgrade plan (`native-wrapper` only)

**Status:** draft plan. No upgrade work has started. Nothing here changes code.

Sources: Perplexity research (2026-11-18) over Expo changelogs / docs, plus a
repo inspection. Items marked **unverified** need a real check before relying on them.

See also: [`expo-eas-ios-build.md`](expo-eas-ios-build.md),
[`expo-eas-android-build.md`](expo-eas-android-build.md).

## Why

- App Store Connect warning ITMS-90725: from **April 2027** uploads must use the
  **iOS 27 SDK (Xcode 27+)**. SDK 55 builds on Xcode 26.2 (iOS 26.2 SDK).
- Apps built with Xcode 27 launch on **iOS 27** only if they use the **UIKit
  scene lifecycle**. SDK 58 generates scene support by default. SDK 55 does not.
- Deadline math: roughly 4.5 months from this draft. See "Schedule": SDK 58 in
  production by end of January 2027, Bare Kit 3 by mid March 2027.

## Interim image (decided 2026-11-24)

**Decision:** `native-wrapper/eas.json` iOS profiles (`adhoc-ios`, `preview-ios`,
`production`) use `macos-tahoe-26.5-xcode-26.6` while remaining on Expo SDK 55.
Do **not** ship `macos-tahoe-26.6-xcode-27.0` + SDK 55.

**Incident that closed the decision:** Xcode 27 + SDK 55 ad-hoc worked until the
test phone updated to iOS 27.2.1; then ad-hoc and TestFlight preview both died at
launch with UIKit
`___UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption` (`EXC_BREAKPOINT`).
No scene lifecycle in SDK 55 CNG. Details:
[`expo-eas-ios-build.md`](expo-eas-ios-build.md) (Interim EAS image).

**Why hold SDK 58 briefly:** finish notification / peer-wake logic with stable
on-device builds over the next ~5–6 weeks, and prepare the SDK 58 migration in
parallel. Return to Xcode 27 only with SDK 58 (scenes by default). Xcode 26.x
remains App Store–acceptable until the ITMS-90725 cutoff (~1 April 2027).

## Approach

Upgrade **one SDK at a time: 55 -> 56 -> 57 -> 58**, one commit per step, as Expo
recommends. SDK 56 is a short checkpoint (Hermes V1 regression fixed in SDK 57
patches; use `expo@57.0.17` or newer).

Cost rule: intermediate steps are validated **without paid iOS builds**
(see "Checkpoint gate"). Paid iOS builds happen only on SDK 58, one at a time:
`adhoc-ios` -> `preview-ios` -> `production`
(see `.cursor/rules/ios-eas-build-cost.mdc`).

### Checkpoint gate (every SDK step, no EAS cost)

Run from `native-wrapper/` (suggested, run by the maintainer):

```bash
npx expo install expo@^<N> --fix
npx expo-doctor@latest
npx expo prebuild --platform ios --clean --no-install
npm run test:bare
```

Then from repo root: `npm run lint`, `npm run check`, `npm run types`, `npm test`.

After prebuild, **inspect the generated `ios/<App>/AppDelegate.swift`** and confirm
the `withGnhBackgroundSync` patch applied (see work item 1). Android can be
validated locally with `npm run android:release` when the toolchain is available.

(`react-native-bare-kit` 0.17.x). B is scheduled right after A, not open-ended:

- One paid iOS build at a time, in the gate order (see

- If A slips past mid Feb 2027, drop B's TestFlight step in favor of shipping A
  alone, and move B to after April (A alone already meets ITMS-90725).

## Repo-specific work items

1. **`plugins/withGnhBackgroundSync.js` AppDelegate patch (highest risk).**
   It regex-matches the `didFinishLaunchingWithOptions` signature and, on no
   match, silently does nothing. SDK 58 moves React Native startup into
   `ExpoAppSceneDelegate`, so the template changes.
   - Make the plugin **fail loudly** when the anchor is not found.
   - Prefer an `ExpoAppDelegateSubscriber` over text patching (Expo's recommended
     path, `expo/fyi` subscribing-to-app-events). Keep `internal import` rules
     (Swift 6).
   - Add a plugin test next to `tests/native-wrapper/with-gnh-security-plugin.test.ts`.
2. **Scene lifecycle and background work.** `BGTaskScheduler` registration and
   `UIApplication.didEnterBackgroundNotification` must still fire under scenes.
   Expo issue 52878 reports scene-less background relaunch may not start JS
   (**unresolved**). Test remote-node background sync and peer-wake pushes on a
   **physical iOS 27 device**.
3. **`ios-native/GnhNotifications` and `expo-notifications`.** SDK 58 shows
   foreground notifications by default and adds iOS delegate forwarding.
   Review `GnhNotificationCenterDelegate.swift` for duplicate or conflicting
   `UNUserNotificationCenter` delegate handling, and set an explicit
   `setNotificationHandler` policy if JS owns it. Re-check
   `docs/features/local-background-notifications.md`.
4. **`react-native-bare-kit`: keep 0.13.3 for SDK 58, migrate in a separate
   change.** See "Bare Kit investigation" below. The `^0.13.3` range stays on
   0.13.x (caret on 0.x), so it will not jump to 0.17 by accident. Verify on the
   free local Android release build, then on `adhoc-ios`.
5. **`expo-file-system` (legacy confirmed present).** `expo-file-system/legacy`
   is still exported in 58.0.14 with `StorageAccessFramework` and
   `bundleDirectory` (verified from the npm tarball, 2026-11-18). The modern API
   has no SAF picker or bundle-directory replacement, so keep the legacy import
   for `src/saveTextFileFromWebView.ts` and `src/bundledUiUri.ts`. Required code
   change: `File.write()` is async in SDK 58. Await it (or use `writeSync`) at
   `saveTextFileFromWebView.ts` lines 45 and 112. `loadWorkletBundle.ts` already
   awaits `bytes()`. Add a test for the save path.
6. **`expo-sharing`.** Shared-file cache is cleaned after 24 hours and by
   `clearSharedPayloads()`. Copy anything needed longer into app storage.
7. **`expo-crypto`, `expo-asset`.** Take the aligned patch versions; test digests
   and bundled-asset loading in a **release** build (R8 on Android).
8. **`expo-status-bar` / `expo-splash-screen`.** `App.tsx` uses `<StatusBar style="light" />`
   and `SplashScreen`; both appear unaffected by removed props, but verify on a
   release build.
9. **`expo-build-properties`.** Keep Android `minSdkVersion: 29` and
   `buildArchs`. Do **not** add `ios.enableSceneSupport` on SDK 58 (no-op there;
   only needed on SDK 57 + Xcode 27). Set the iOS deployment target via the
   built-in app config property, not the deprecated plugin option.
10. **WebView 13.16.0 -> 14.0.1.** Re-run WebView-dependent flows: bridge inject,
    navigation allow-list, file save, clipboard, keyboard inset
    (`tests/native-wrapper/webview-navigation.test.ts`, `inject-mobile-bridge.test.ts`).
11. **Android R8.** Release builds minify by default in SDK 58. Exercise all
    native modules (`Gnh*` Kotlin, Bare worklet) in a minified release APK and add
    keep rules if needed; opt-out is `android.enableMinifyInReleaseBuilds: false`.
12. **Android toolchain.** CI installs platforms 35/36 only
    (`.github/workflows/build-signed-apk.yml`). SDK 58 uses **compileSdk 37**:
    add `platforms;android-37` and matching build-tools. Expect Gradle 9.4.x,
    AGP 9.x, Kotlin 2.2, JDK 17 on EAS; keep CI JDK at 21 unless it breaks.
13. **Version script.** `scripts/apply-expo-version.mjs` edits `app.json`; confirm
    it still works if `app.json` gains new keys. `appVersionSource` stays `remote`.
14. **React / RN typing.** SDK 58 uses strict RN TypeScript APIs and removes some
    RN APIs. Run `npm run types` for `native-wrapper/src` and `App.tsx` and fix
    deep imports from `react-native/Libraries/*` if any appear (none found today).

## Validation (SDK 58 only, paid builds)

Run one at a time, stop on first failure, fix, and rebuild that gate:

1. Local: checkpoint gate on SDK 58, plus `ios/` prebuild inspection.
2. `eas build -p ios --profile adhoc-ios` -> install on registered devices:
   one **iOS 27**, one older supported iOS (16.4+). Check launch, unlock
   (Face ID), pairing, chat, background sync, peer-wake push, local
   notifications, file save/share, WebView UI, splash.
3. `eas build -p ios --profile preview-ios` -> TestFlight -> `production` only
   after step 2 and TestFlight pass.
4. Android: local or EAS APK on devices near min (API 29) and target (API 36),
   release/R8 build, background sync, notifications.

Before any upload, confirm the remote iOS build number is higher than App Store
Connect's: `eas build:version:get -p ios`.

## Bare Kit investigation (2026-11-18)

Latest is `react-native-bare-kit` **0.17.1** (2026-11-03). Peer deps are still
`react: *`, `react-native: *`, so npm will not block RN 0.88. No upstream issue
mentions RN 0.84-0.88, Expo SDK 58, Xcode 27 or iOS scenes (none confirms it
works either: **unverified**).

0.13.3 -> 0.17.x is a **Bare Kit 3 migration**, not a bump
(@see https://docs.pears.com/bare/how-to/run-on-native/migrate-to-bare-kit-3/):

| Area | 0.13.3 (today) | 0.17.x |
|------|----------------|--------|
| Native Bare Kit | prebuilt `BareKit.xcframework` and Android `.so` shipped in the package | **not shipped**; linked by the app with `bare-stow link --target bare-kit` |
| Addon linking | podspec `prepare_command` runs `link.mjs` (bare-link); `scripts/link-bare-addons.mjs` on Android | `bare-stow`; Expo apps use `expo-bare-kit` >= 0.3.0 |
| Worklet global | `BareKit.IPC` in `bare/entry.mjs` | `BareKit` global removed; use `Bare.IPC` |
| `worklet.start` | current call sites | `assets` option removed; in 0.15.6-0.17.1 pass an explicit args array |
| iOS entitlement | none | extended virtual addressing for Bare Kit >= 3.1 (**unverified** for our app; affects App ID and provisioning) |
| Platform minimums | iOS follows RN; Android `minSdk` 29 | same in the package; linked Bare Kit docs say iOS 15 / Android 10 |

Decision: **do not combine** the Bare Kit 3 migration with SDK 58. Ship SDK 58 on
0.13.3 first, then open a second plan covering `bare-stow`, `expo-bare-kit`, the
`Bare.IPC` change, the iOS entitlement and the EAS pre-install scripts. If 0.13.3
fails on RN 0.88 or Xcode 27 during the SDK 58 step, that second change becomes
a blocker for SDK 58 and must come first.

Risk to remember: 0.13.3 is old and the upstream line has moved on. Stay on it
only as long as it builds and runs. Do not bump it to 0.14-0.16 as a halfway step.

## Rollback

Each SDK step is its own commit. If SDK 58 blocks, revert to the last passing
step. For shipping iOS builds before April 2027, the Xcode 26.6 image on SDK 55
remains valid (see "Interim image").
