Get NowHere is not a public-room product. Connectivity is relationship-based.

## Discovery is derived, not named

The runtime joins a derived topic built from relationship identifiers. Human
room titles are not used as raw network topics. After a transport peer
appears, the application still runs a **post-connect check** before the
composer is trusted. Topic join alone is not identity.

The exact derivation formula and bridge message catalog stay in the internal
engineering docs. They are not republished here.

## Who owns the swarm

| Host | Swarm owner | Status |
| --- | --- | --- |
| Web development | Node sidecar | In use for local development |
| Desktop | Sidecar child / shell-owned process | In use for desktop development and packaging |
| Mobile | Bare worklet | **Planned** on-device host |

The UI always remains a client of the bridge.

## Live path versus fallback

When the live session is up, frames travel on a **double-encrypted** peer
stream (application seal plus transport). When it is not, Conceal-backed
relay keeps the room moving without parking plaintext on a chat server.
Relay is availability, not a different privacy product.

A live punch is only with someone you already invited. The session does
not show IPs. Either counterpart could, with dedicated software, extract
the other person’s IP — they already decided to talk. That still does
not decrypt the room.

## Connectivity guarantees

This page does **not** claim:

- successful hole punches on every network
- that every published binary includes the same runtime
